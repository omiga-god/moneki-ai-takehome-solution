## 这是什么

一个给运营用的问答服务。
两条线：一条查销售数据库（`data/pos.db`），一条查公司知识库（`knowledge_base/`）。
问句进来先过一遍规划，判断是要查数还是查文档，然后取数或者检索，最后拼成一段中文回答。

系统的“今天”写死在 `kbqa/config.py` 里，是 2026-09-01，别改，运营那边的口径就是按这个来的。

## 怎么跑

```bash
make setup      # 建虚拟环境、装依赖
make rebuild    # 重建清洗表和检索索引
make run        # 起服务，默认 8000 端口
make test       # 跑测试
```

换数据或者换知识库的时候：

```bash
make rebuild DATA_DIR=/path/to/data KB_DIR=/path/to/knowledge_base
```

`DATA_DIR`、`KB_DIR` 也能直接当环境变量传给 `make run`。

## 目前的状态

- **检索命中率 95%**。上线前我自己抽了 20 题人工看了一遍，19 题的第一条就是对的文档，剩下一题排在第三。这个数我一直拿来跟运营汇报。
- **测试全部通过**。`make test` 是绿的，我走之前还跑过一次。
- **md、txt、html 三种格式都支持**。知识库里那几个 `.txt` 和 `.html` 的老文件也能正常进索引，当时专门试过。

## 几个要知道的地方

- 索引建好之后会写在 `.cache/index.json`，第一次起服务会慢几秒，之后就直接读缓存了，很快。这个文件我提交进仓库了，新同学 clone 下来不用等建索引。
- 大模型这块走环境变量 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`，不配也能跑，会走本地的模板回答。Key 别提交。
- 清洗后的销售表在 `var/clean.db`，`var/` 没进仓库，`make rebuild` 会重新生成。
- 支付方式、门店名、商品名这些都从数据库读，代码里没写死。

## 已知的小问题（没来得及弄）

- 运营偶尔反馈说“答非所问”，我看了几次都是问题问得太笼统，让他们问具体点就好了。
- 追问（“那 7 月呢”）有时候接不上，重新问一遍完整的就行。
- 月底那几天的数字跟财务对不太上，差得不多，应该是四舍五入的事，回头有空再看。
