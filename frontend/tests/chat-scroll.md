# 对话滚动回归（真实浏览器）

在运行的工作台中新建对话，保持鼠标不在对话记录内滚动。

1. 连续发送四次“7 月净营业额是多少？”，每次等待发送按钮恢复。
2. 对话框应包含八条消息；最后一条回答应处于可见区域。检查 `.chat` 的 `scrollHeight - clientHeight - scrollTop <= 2`。
3. 向上滚动查看第一条消息，新回答到达时不应把阅读位置强制拉回底部；应显示“有新回复 · 回到最新”按钮。
4. 点击“回到最新”，滚动差应回到 2 像素以内，按钮消失。
5. 从历史位置主动发送新问题，应回到最新；请求失败时错误消息也应可见。
6. 新建对话后清空消息和未读提示，重复步骤 1–2 仍通过。

步骤 1–2 是本次缺陷的回归门槛：修复前新增消息仅追加 DOM，容器保持旧 scrollTop，因此溢出后失败。可使用浏览器开发工具只读检查消息数量与几何位置，不将测试代码加入业务页面。
