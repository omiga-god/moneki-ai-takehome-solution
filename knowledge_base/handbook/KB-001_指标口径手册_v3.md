# 指标口径手册 v3

适用范围：总部运营部、财务部、各门店店长，以及所有基于 POS 导出数据出具的经营报表与对外口径。
本手册自 2026-05-01 起生效，取代 v2（KB-002）。此前的模板、表格、月报里凡与本手册不一致的算法，一律以本手册为准。

## 1. 数据来源

经营数字的唯一来源是 POS 每日导出的销售明细表 `sales`，配合门店维表 `stores` 与商品维表 `products`。
`sales` 的字段为：`order_id`、`date`、`store_id`、`product_id`、`qty`、`amount`、`payment`。
导出文件不做任何人工修改，所有清洗动作都写在本手册里由系统统一执行，门店和总部都不得先改数再报数。

## 2. 规范化

在做任何筛选和汇总之前，先按下面四条把字段规范化。

1. `store_id`、`product_id`：去掉首尾空白，并转为大写。`s01`、`S01 `、` s03` 这类写法规范化之后都是合法的编号，不要当成脏数据扔掉。
2. `date`：接受三种格式，`YYYY-MM-DD`、`YYYY/M/D`、`DD-MM-YYYY`。
   第三种是旧 POS 的导出格式，**日在前、月在后**：`25-07-2026` 是 2026 年 7 月 25 日，`07-06-2026` 是 2026 年 6 月 7 日。
   这一类里会出现“日”大于 12 的样本，正好可以用来验证解析方向有没有搞反。
3. `amount`：去掉 `¥` 前缀与首尾空白之后按数字解析。`¥38.00` 与 `38.00` 是同一个金额，带符号的行是可恢复的，必须保留。
4. `qty`：按整数解析。

## 3. 剔除（按顺序执行）

1. 日期无法解析的行。
2. `amount` 为空的行。**不回填**，直接剔除。
3. `qty ≤ 0` 的行。
4. 规范化后 `store_id` 不在 `stores` 表里的行。
5. 规范化后 `product_id` 不在 `products` 表里的行。
6. 规范化后所有字段完全相同的重复行，只保留 1 条。

关于第 6 条要特别说明：只有订单号、日期、门店、商品、数量、金额、支付方式这七个字段规范化之后**完全一致**的行，才算重复行。
一张订单点了两个不同商品时会出现两行明细，它们共用同一个 `order_id`、同一个日期、同一家门店、同一种支付方式，只有商品不同，这是合法的多行订单，必须全部保留。
一句话：完全相同的重复行要去掉，共用订单号的不同商品行要留下。

## 4. 指标定义

- **退款行**：通过上述剔除规则后 `amount < 0` 的行。
- **销售行**：通过上述剔除规则后 `amount > 0` 的行。
- **净营业额** = 销售行金额之和 + 退款行金额之和。退款行的金额本身是负数，所以实际效果是相减。
- **退款金额** = 退款行金额之和的绝对值。
- **有效订单数** = 销售行中不同 `order_id` 的个数。多行订单算 1 单；退款行不单独计为订单。
- **客单价** = 净营业额 ÷ 有效订单数，四舍五入保留 2 位小数。
- **销量** = 销售行 `qty` 之和减去退款行 `qty` 之和。
- 按日期、门店、商品筛选时，退款行按**退款行自己的日期**归属，不回溯到原单日期。

## 5. 数字来源优先级

1. 凡涉及营业额、订单数、销量、客单价等经营数字，一律以数据库按本手册口径计算的结果为准。
2. 周报、会议纪要、活动复盘里的数字是店长和运营的人工估算，只能当背景参考，不能当作答案，更不能拿去对外。
3. 商品的现行售价以调价通知为准。`products` 表里的 `unit_price` 是建档价，由财务在月底统一更新，可能滞后于实际售价，不能用它当作某一天的成交价。
   **金额以实收为准**：`amount` 记的是顾客当时实际付掉的钱，活动特价、调价当天的差异都已经体现在 `amount` 里，不要用建档价反推金额，也不要用建档价去覆盖 `amount`。

## 6. 变更记录

| 版本 | 生效日期 | 状态 |
|---|---|---|
| v3 | 2026-05-01 | 现行 |
| v2 | 2025-09-01 | 已被 v3 取代 |

v3 相对 v2 改了三个地方，都会直接改变算出来的数字，做同比同环比时请注意：

1. 退款行改为计入净营业额。v2 把负金额行在清洗阶段直接剔除，只统计正向销售，退款另走财务台账。
2. `amount` 为空的行改为直接剔除。v2 是按 `qty × unit_price` 回填后继续参与统计。
3. 客单价的分母改为有效订单数。v2 用的是明细行数，多行订单会被算成多单，客单价偏低。

另外 v3 新增了四段说明：`DD-MM-YYYY` 日在前的解析方向、“金额以实收为准”、合法多行订单与重复行的区分、以及第 5 节的数字来源优先级。
这几段在 v2 里没有对应内容，不属于口径变更，属于把原来靠口口相传的做法写进手册。

## 7. 几个最容易搞错的地方

1. 带 `¥` 的金额是可以恢复的脏值，去掉符号之后照常参与统计，不要把整行丢掉。
2. 门店编号大小写不一致、前后带空格，都属于可恢复的写法，要先规范化再判断是不是脏外键，顺序反了会误删真实订单。
3. 同一个订单号出现多行时，先比对全部字段：字段完全一样的是重复行，只留一条；商品不一样的是一张订单里点的多个菜，必须全部保留，订单数仍然只算 1 单。
4. 退款行的日期是操作退款那一天，不是原订单那一天。算某一天、某一家门店的数时，按退款行自己的日期归属，不要挪回原单。
5. 某个商品在某一天的成交单价和建档价对不上时，以 `amount` 为准，不要去“修正”它，也不要因此把这些行当成脏数据。
6. 报表数字和门店口头汇报对不上时，先按本手册重算一遍，再谈差异原因，不要直接采信任何一边。
